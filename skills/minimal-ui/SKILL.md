# Skill — Minimal Necessary UI

## 目的

UI 只保留用户完成当前任务所需的最少按钮、最少提示和最少信息。

## 决策规则

新增任何 UI 元素前依次判断：

1. 用户当前是否必须知道/操作它？
2. 能否自动检测或默认完成？
3. 是否与已有操作重复或近义？
4. 删除它后，用户是否仍能正确完成任务？
5. 是否只在错误/风险出现时才需要展示？

只要可以删除而不影响正确完成任务，就不新增。

## 具体约束

- 一个页面优先一个主操作。
- 次级按钮仅用于独立且必要的路径。
- 不为成功状态堆叠说明。
- 不显示普通用户无需理解的端口、PID、fingerprint、协议字段。
- 高级项折叠到设置/诊断。
- 风险提示必须短、具体、可行动。
- 不使用冗余卡片、营销式文案、重复标题和重复状态。
- 首次引导每屏只解决一个决策。

## LocalBridge 特例

Wizard Screen 2 的“打开 ChatGPT MCP 应用页”是已批准的必要次级操作，不视为冗余。


## 必要状态例外

Dashboard 管理员权限状态属于必要状态，不因“最小 UI”而隐藏。

原因：

- Elevated 偏好与 Broker Active 是两个不同状态；
- 用户必须知道当前 AI 是否实际拥有管理员执行能力；
- 这是安全边界，不是诊断噪音。

因此主界面必须显示管理员权限状态，但只显示简化结果与必要动作。

## 界面语言

- 能用准确中文表达，就不额外显示英文。
- 不做中英双语标签堆叠。
- 专业缩写只在确有识别价值时保留。

## 当前任务状态

当前任务是必要状态，不属于消息流。

只显示：

```text
类型
任务
状态
```

没有任务时收敛为：

```text
状态：空闲
```

禁止最近活动列表、历史卡片、时间线或滚动日志。

## 单行执行状态

执行状态不得做成状态卡片。

正确：

```text
●  运行测试  cargo test
```

错误：

```text
当前任务
类型：运行测试
任务：cargo test
状态：执行中
```

活动状态只使用绿色小圆点的轻量脉冲表达，不增加文字噪音。
