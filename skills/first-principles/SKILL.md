# Skill — First Principles Engineering

## 目的

所有设计、修复和实现从问题本质出发，而不是从现有代码形状或惯例出发。

## 执行规则

1. 明确目标、输入、输出、约束、不变量与失败模式。
2. 区分根因与症状；优先修复根因。
3. 任何新增抽象都必须由当前真实需求证明。
4. 对既有实现保持可质疑：旧代码只能作为证据，不能自动成为正确性来源。
5. 方案比较优先使用：正确性 → 安全边界 → 可维护性 → 简洁度 → 开发速度。

## 禁止

- 因为“现有项目这么做”而无条件复制。
- 为通过单个测试而破坏更高层合同。
- 用额外分支和特殊案例掩盖错误状态模型。
